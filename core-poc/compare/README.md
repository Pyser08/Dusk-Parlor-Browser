# core-poc/compare: 실제 리수 요청 로그와 대조

실제 리수 요청 로그(JSON)와 그때 쓴 캐릭터 파일(.charx)을 받아, 같은 캐릭터를 우리 코어로 돌린 결과와 메시지 단위로 비교해요.
사용자의 로그와 캐릭터 파일은 개인 자료라 저장소에 넣지 않아요.

## 준비
- `charx/`: .charx 압축을 푼 폴더 (`card.json`, `module.risum`)
- `module.json`: `module.risum`을 리수의 rpack 표(`src/ts/rpack/rpack_map.bin`의 뒤쪽 256바이트)로 풀어 낸 JSON
- `log_messages.json`: 요청 로그의 `messages` 배열
- 캐릭터 구성은 리수 `importCharacterCardSpec`의 필드 대응을 그대로 따라요. charx는 모듈의 로어북·정규식·트리거가 캐릭터에 붙어요.
- `FM_IN_CHAT=1`을 주면 첫 메시지를 대화 기록에 넣고 돌려요.

## 결과 (2026-11-12, 캐릭터: 로어북 125개, 정규식 58개, Lua 트리거 1개)
- 로그 84개 메시지 대부분은 사용자 프리셋, Dusk 플러그인, 따로 장착한 모듈에서 나온 것이라 대조 대상이 아니에요.
- **캐릭터에서 나온 메시지는 17개가 글자 하나까지 같았어요.** 첫 메시지(CBS 분기 다수), 로어북 항목 13개, 사용자 입력, 시스템 메시지, 프로필 규칙이 여기에 들어가요. 설명은 프리셋이 붙인 머리줄 한 줄을 빼면 본문이 같았어요.
- **원인이 밝혀진 차이**
  - 키워드 로어북 2개('헌터', '최유진'): 리수 원본은 로어북을 찾을 때 첫 메시지를 훑지 않아요. 첫 메시지를 대화 기록에 넣으면 두 항목 모두 똑같이 맞아요. 사용자 환경(포크나 플러그인)의 동작 차이로 보여요.
  - 이미지 명령 안내의 NSFW 단락: 카드에 없는 내용이에요. 외부 모듈에서 붙은 것이에요.
  - NPC 목록 일부: 카드의 Lua 트리거가 대화를 훑어 NPC 변수를 바꾸는데, 우리 쪽 Lua는 아직 자리표시자예요.
- 한 번 실행하는 데 약 50~90ms 걸렸어요(일반 Node, 약 2만 5천 토큰짜리 프롬프트). JIT 없는 iOS JavaScriptCore에서는 더 느릴 거예요. 아직 재 보지 않았어요.
- 이 카드의 정규식은 lookbehind와 `\p{Extended_Pictographic}`을 써요. iOS 16.4 이상 JavaScriptCore가 지원하는 문법이라, 최소 지원 버전 iOS 17과 맞아요.
